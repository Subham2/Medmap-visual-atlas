What made it "a static collection of texts"

Five independent faults each caused a silent switch to offline data:

  1. Proxy ignored. Node's built-in fetch does not read HTTPS_PROXY; every provider call failed with ENOTFOUND.
  2. Gateway time cap. The gateway terminates requests at about 30 s. Ten cases or a multi-thousand-word mind map in one call cannot finish in time.
  3. Concurrency cap. The key allows 5 simultaneous requests; bursts returned HTTP 429 "Concurrency Limit Exceeded".
  4. Slow default model. gemini-3.5-flash failed most large chunks inside the cap.
  5. Invented image URLs. The model fabricated plausible Wikimedia file names; the verifier rejected every one as a 404.
Security action required Two provider keys must be rotated in the provider dashboard: the key that was hard-coded in the original server.ts (prefix sk-live-c785…) and the key shared in the development conversation. Neither is in any commit; the current key exists only in a git-ignored local .env.

6AI pipeline

6.1 Provider resolution

  • No GEMINI_API_KEY: offline mode (curated data). Nothing is hard-coded.
  • A Google key (AIza…): Gemini API directly via @google/genai.
  • Any other key with GEMINI_BASE_URL: an OpenAI-compatible /chat/completions endpoint, with JSON response mode when structured output is needed.
  • Optional AI_BACKUP_BASE_URL / AI_BACKUP_API_KEY: failover used only when the Gemini route fails.

6.2 Measured provider limits (aicredits.in)

PropertyObservedDesign response
Request time capHTTP 500 "Internal Server Error" at ≈ 30 sChunked generation; 28 s per-attempt timeout leaves time to fail over
Concurrency5 parallel requests per key; the 6th returns 429Process-wide semaphore, 4 slots; 429 waits and retries the same model (≤ 3 times)
Bad credentials401 / 402 / 403Stop immediately (1 upstream call instead of 4)
Malformed JSONOccasional invalid escapes (e.g. LaTeX \()Parser repairs invalid escapes and control characters, then retries the parse

6.6 Image retrieval

  1. Search Wikimedia Commons (file namespace, bitmap only) for the topic; keep JPEG/PNG/GIF/WebP files with CC or public-domain licences, excluding NC/ND.
  2. The model selects 2–4 medically relevant candidates by index and writes teaching points and a pathology correlation. It never supplies URLs.
  3. The verifier scores each image out of 100: source credibility 25, licence clarity 25, live URL and image content-type 20, medical relevance 15, metadata completeness 10, quality 5. ≥ 80 is verified, ≥ 60 needs review, otherwise rejected. It checks the original file and displays the thumbnail.
  4. An identifying User-Agent, a per-topic result cache and a Retry-After cooldown comply with Wikimedia's rate-limit policy.

7Offline mode and content integrity

Offline mode activates when no key is configured or a provider call fails. It is designed never to present invented, topic-specific "facts".

ContentOffline behaviour
CasesCardiac topics use the 10-case cardiac generator; stroke and PE topics get their curated case; anything else gets the three curated cases. Previously, MI cases were relabelled for any topic (an "Asthma" case had ST-elevation ECGs).
Symptom mapCurated MI map; other topics get a structured reasoning template clearly labelled "OFFLINE TEMPLATE".
Mind mapsCurated content for MI, aortic dissection, DKA, pneumothorax, anaemias and sideroblastic anaemia; generic scaffold otherwise.
ImagesCurated verified images only when the topic matches; otherwise none. Previously, unrelated images were shown as "verified".
Drug interaction, symptom analysis, quizRule-based answers for common patterns; generic guidance otherwise.

Every response carries source; the UI shows AI or OFFLINE badges and a header state indicator.

Optimizations applied

  • Server: response cache with in-flight de-duplication (repeat requests made 0 upstream calls in testing); parallel image URL checks (worst case 6 s instead of 18 s per image); early stop on auth errors; per-attempt timeouts; about 450 lines of dead fallback data removed from server.ts.
  • HTTP: hashed assets served with Cache-Control: immutable, max-age=1y; index.html revalidated on every load.
  • Client: lazy tabs and export libraries; abortable requests (no stale state after topic changes); ECG animation pauses when the tab is hidden and respects reduced-motion settings; pair results cached in the drug matrix.
  • Usability: removed page-wide select-none so learners can copy text; added missing Tailwind shades; mobile header no longer overflows.

Docker

curl http://localhost:3000/api/readiness

Reverse proxy and probes

  • Terminate TLS at Nginx or a load balancer and proxy to port 3000 with X-Forwarded-* headers; set TRUST_PROXY=1.
  • Proxy read timeout ≥ 60 s (chunked generation takes about 20 s, with headroom for retries).
  • Liveness probe /api/health; readiness probe /api/readiness.
  • The host must reach the AI provider, commons.wikimedia.org, upload.wikimedia.org, creativecommons.org and Google APIs.

CI pipeline (GitHub Actions, Node 22)

npm ci → npm run lint → npm run build → npm run check:publish → npm audit --omit=dev --audit-level=high.

15Known limitations and roadmap

  • Single-process state. The rate limiter, AI cache and concurrency semaphore are per process. For multiple replicas, move them to Redis or enforce limits at the gateway.
  • AI content accuracy. Output is model-generated and spot-checked, not clinically validated. A clinician review workflow, or citations to guideline sources, would be needed for formal teaching use.
  • Wikimedia dependence. Image retrieval is subject to Wikimedia rate limits. An API token or a pre-built curated image index would remove this.
  • Logging. Some legacy handlers still log plain text; migrate them to the JSON format.
  • Unused heavy dependencies. @huggingface/transformers and @mlc-ai/web-llm are installed for the WebGPU tier but not yet wired to inference. Implement that tier or remove them to cut install size.
  • Tests. Coverage is the end-to-end gate plus browser runs; unit tests for the chunk merge and validators would harden refactors.
